# 論点台帳: 何が決まっていて、何が決まっていないか

- 作成日: 2026-09-18
- 位置づけ: 01〜08 と `poc/` に散在する未確定事項を 1 か所に集め、「決め手は何か・いつまでに・誰が」を付けたもの。各論点は決まり次第、該当文書に反映してここから消す。
- 読み方: §1 は再論しない決定事項。§2 が本題で、次の一手を止めている順に並べている。§3 は決定に必要な情報の一覧。

## 0. 要点

決まっていないことは 3 種類に分かれる。

1. **要件側の回答待ち。** 2026-09-20 に大半が回答された(業種は自動車保険で事故対応外、書き起こし様式、業務メタデータなし、マスキング未実施、ローカル LLM 前提の可能性)。残るのは費用上限(Q2-c)と v1 の運用(Q7)のみ。合成コーパスの仕様は [10](10_synthetic_corpus_spec.md)。
2. **文書間で立場が食い違っている(3 件)。** 02 のテーマ定義エンジン、01 の PPI 補正・蒸留、02 と 07 の「通話 1 件 = 1 行」表現。放置すると後の文書がどちらを前提にしているか分からなくなる。
3. **設計者側で決められるが、実測がないと決めきれない(残り)。** 語彙進化の閾値、抽出の段数、モデル選択など。PoC の自動実行が前提。

したがって最初の一手は、10 の仕様に沿って生成器を実装し第 1 段 300 件を作ることと、抽出用ローカル LLM の候補を決めること(SD9)の 2 つ。

## 2. 未決の論点

凡例: 期限 = **今**(次の作業を止めている)/ **PoC**(自動抽出の実測後)/ **v1**(本番設計時)/ **要件時**(要件が出たら)。決定者 = 依頼者(要件・環境・データの所有者)/ 設計(本検討の担当)/ 分析者(将来の利用者)。

### 2.0 合成データで進めることの帰結(P1 の回答を受けて)

実データがないため、PoC は合成通話で行う。02 §6 の基準のうち何が測れて何が測れないかを先に固定する。

| 02 §6 の基準 | 合成データで | 備考 |
|---|---|---|
| 引用の逐語一致率 | **測れる** | 抽出器の性質なので入力が合成でも成立 |
| 合成データでの再現率・適合率(混乱、テーマ該当、境界例) | **測れる** | もともと合成前提の基準。正解ラベルは生成時に埋め込む |
| 判断列の 2 モデル一致(κ) | **測れる** | 同上 |
| 外部整合(`unresolved` → 7 日内再入電) | **測れない** | CRM 側の事実も合成すると循環する。v1 で実データが入ってから |
| 既知事例の盲検再現 | **条件付きで測れる** | 真因シナリオを埋め込んだ合成コーパスで代替。**シナリオを決める人と分析する人を分ける**(SD3)。同一人物なら「盲検」にならない |
| 分析者の根拠 30 件目視 | **測れる(弱い)** | 合成通話は生成モデルの文体に寄るため、過検出の実態は実データより楽観的に出る |
| 分析者の体感 | **測れない** | 実テーマがない |

合成データの限界も明記する。(1) 生成モデルと抽出モデルが同系なら一致率が過大評価される。生成と抽出は別モデル(または別ベンダー)にする。(2) ASR 誤りとフィラーを模擬しないと実データより易しくなる。数字・固有名詞の誤認識、言い淀み、話者の混在を意図的に注入する(SD4)。(3) 「未知の未知」は合成できない。語彙進化(04)の検証は「意図的に語彙から外したテーマを検知できるか」に限定する。
