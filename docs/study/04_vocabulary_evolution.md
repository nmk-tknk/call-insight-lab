# 語彙の自動進化: 新タグの検知・生成・検証・採用を自動化する

- 作成日: 2026-09-14
- 経緯: 03 では語彙改訂を人手前提で書いていた。語彙は年々増えるため、その検知と更新はツールの中核スコープとする。
- 位置づけ: 「汎用」の意味を「スキーマが固定」から「**スキーマを育てる手順が固定**」に改める。

## 0. 要点

- 汎用性の源泉は固定スキーマではなく、**どの列にも同じように働く語彙進化ループ**にある。`reason` / `trigger` / `touchpoint` / `product` すべてに同じ機構を適用する。
- ループは「検知 → 候補生成 → 自動検証 → 暫定採用 → 安定化 → 履歴の整合」の 6 段で、**人の関与は拒否権(veto)と週次ダイジェストの確認のみ。** 承認待ちで止まらない。
- 語彙は追加優先・階層構造・写像表付きで管理し、**新タグが増えても過去の時系列が壊れない**ようにする。

## 1. 何を自動検知するか(シグナル)

| シグナル | 検知方法 | 意味 |
|---|---|---|
| `other` 率の上昇 | 列ごと・期間ごとの管理図(CUSUM / EWMA) | 語彙に穴がある |
| 新しい塊の出現 | `other_text` と `request_summary` の埋め込みを週次で増分クラスタリング。既存タグのプロトタイプから遠く、複数週にわたり成長する塊 | 新テーマ・新接点 |
| 既存タグ内部の分裂 | タグ配下の埋め込み分散の増大、重心の移動、下位クラスタの出現 | タグの粒度が粗くなった(分割候補) |
| 判定の不安定化 | 特定タグでの複数モデル不一致率・低確信率の上昇 | 定義が現実とずれてきた |
| 新規性スコアの上昇 | 各通話の「最近傍タグまでの距離」の分布が右に寄る | 未知のものが増えている |
| 消滅 | タグの件数が N 期間ゼロ近傍 | 退役候補(削除はしない) |

いずれも件数と埋め込みだけで計算でき、LLM 呼び出しは不要。日次または週次のバッチで回る。

## 2. 候補の自動生成

検知された塊ごとに LLM が次を生成する(TopicGPT / LLooM / Clio と同じ手順)。

1. タグ名と 1 文の定義
2. 包含基準・除外基準・境界例(これがそのまま抽出プロンプトの一部になる)
3. 階層上の位置(どの `reason_l1` の子か、既存タグの分割か、完全に新規か)
4. 既存タグとの関係(近い既存タグと、その違い)
5. `touchpoint` の場合: 社内の成果物マスタ(書類・画面・手続き一覧)との照合。一致すればそのコード、なければ「マスタ未登録」フラグ付きの新コード

## 3. 自動検証(採用前ゲート)

候補は以下をすべて満たしたときだけ次段へ進む。すべて自動。

| 検証 | 基準(案) |
|---|---|
| 規模 | 直近 4 週で該当 N 件以上(例: 月 10 万件なら 50 件以上) |
| 持続 | 連続 2 期間以上で出現(単発のスパイクは候補のまま保留) |
| 分離 | 候補定義を既存タグ配下のサンプルに適用したとき、既存タグとの重複率が閾値以下(例: 20%)。超える場合は「分割」または「統合」候補として扱う |
| 一貫性 | 候補定義を該当サンプルに 2 モデル(または言い換えプロンプト 2 種)で適用し、一致 κ ≥ 0.7 |
| 凝集性 | LLM 判定で塊内サンプルの 80% 以上が定義に合致(Dial-In LLM のクラスタ一貫性判定と同型) |
| 分割半分再現 | 塊を無作為二分し、両半分で同じ候補が生成される |
| 階層整合 | 親タグの件数が候補追加の前後で変わらない(子の追加として扱えること) |

## 4. 採用ポリシー: 暫定採用+拒否権

- **検証を通過した候補は自動で語彙に追加される(tier = provisional)。** 以後の抽出で選択肢に含まれ、出現期間ぶんは `other` と近傍タグの該当分のみを対象に再抽出(バックフィル)する。全件再抽出はしない。
- 暫定タグはレポート上で「暫定」と表示される。集計には含まれるので、急増の真因分析で「語彙にないから見えない」状態が起きない。
- **連続 M 期間(例: 8 週)安定して出現し、判定一貫性を保てば自動で stable に昇格。**
- 人は週次ダイジェスト(新規・分割・統合・退役の一覧と根拠サンプル)を受け取り、**拒否・改名・統合を指示できる。指示がなければそのまま進む。** これが「承認」ではなく「拒否権」である理由は、承認待ちが語彙の陳腐化そのものを生むから。
- 退役: N 期間ゼロ近傍のタグはアーカイブし、選択肢から外す。履歴は残る。

## 5. 過去との整合(時系列を壊さない)

語彙が増え続けても集計が比較可能であるために、次を守る。

1. **追加優先・階層構造。** 新タグは原則として既存の親の子として追加する。親レベルの時系列は語彙変更の影響を受けない。
2. **写像表(vocab lineage)。** 分割 `A → A1, A2`、統合 `B, C → D`、改名をすべて `vocab_version` 間の写像として記録する。任意の過去期間を、任意の語彙バージョンで再表現できる。
3. **差分バックフィル。** 語彙変更時に再抽出するのは、影響を受けるタグ配下と `other` の通話のみ。要約列に対する再分類なので費用は小さい(03 のテーマ再分類と同じ経路)。
4. **抽出プロンプトの自動更新。** 語彙は抽出プロンプトの外部データとして注入する。語彙が変わってもプロンプト本文は変わらず、`vocab_version` だけが上がる。
5. **全レポートに語彙バージョンを表示。** 「この数字はどの語彙で数えたか」が常に追える。

## 6. 汎用性の再定義

| 観点 | 03 まで | 本メモ |
|---|---|---|
| 固定するもの | 列と語彙 | 列の**型**(閉じた語彙であること)と、語彙を育てる**手順** |
| 語彙の出所 | 初期に人が凍結 | 初期は LLM 誘導+人の確認。以後は自動進化+人の拒否権 |
| 新テーマへの追従 | `other` を人が見て改訂 | 自動検知 → 暫定タグ → 集計に即反映 |
| 列の追加 | 想定外 | 同じ機構で新しい列(新しい閉じた語彙)も追加できる。例: 「顧客が比較した競合」を新列として定義すれば、語彙はゼロから自動で育つ |

つまり「汎用」とは、**業種・目的・時期が変わっても同じ機構で語彙が育ち、常にタグ集計で数値が出せる状態を保てること**を指す。

## 7. 自動化の限界(正直に)

- **意味の妥当性は保証できない。** 機構が保証するのは、分離・一貫性・持続・階層整合であり、「そのタグが業務上意味のある切り方か」は保証しない。拒否権と週次ダイジェストはこのために残す。
- **断片化のリスク。** 長期運用で近縁タグが増殖しやすい。分離基準と統合候補の自動提案で抑えるが、年 1 回程度の語彙棚卸しは想定しておくべき。
- **接点語彙は業務マスタに依存する。** 新しい書類や画面が出たとき、機構は「顧客が混乱している未知の接点」を検知できるが、正式なコードはマスタ側にある。マスタとの照合を自動化し、未登録は暫定コードで走らせる。
- **モデル更新による語彙のずれ。** 抽出モデルが変わると同じ語彙でも判定境界が動く。合成データ回帰(02 §4)をモデル更新のたびに走らせ、タグ別の再現率変化を検出する。

## 8. 根拠となる研究・事例

- 増分・オープンワールド意図発見: IntentGPT(2024)、LANID(2025)、NILC(2025)、Oracle のライフサイクル対応増分クラスタリング(IJCNLP-AACL 2025)、サービスフィードバックの新興トピック検知(2026)
- タクソノミー生成と一貫性判定: TnT-LLM(KDD 2024)、TopicGPT(NAACL 2024)、LLooM(CHI 2024)、Dial-In LLM(EMNLP 2025)、Clio(2024)
- 製品事例: Intercom Topic Curation(AI 生成トピックを人が統合・改名)、Google CX Insights(発見→凍結→推論)、Enterpret / Unwrap の「自己更新タクソノミー」
- 概念ドリフト検知の古典手法: CUSUM、EWMA、ADWIN
