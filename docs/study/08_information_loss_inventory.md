# 情報量の棚卸し(再整理版): スキーマ v0.3 で何が落ちるか

- 作成日: 2026-09-16、再整理: 2026-09-18
- 対象: `poc/schema/v0_3.sql`
- 問い: このスキーマで情報量が落ちない保証はあるか。落ちるなら、どれを・いつ・どう手当てするか

## 0. 結論

**保証はない。構造化は定義上、情報を落とす。** ただし v0.3 は (1) `turns.text` に発話を逐語で保持し、(2) 注釈をすべてスタンドオフの別表に置き、(3) 新しい表・列・`annotation_run` を足しても既存表と集計が壊れない、という 3 性質を持つ。したがって損失の大半は「消える」ではなく「まだ集計できない」に留まる。

例外は 1 種類だけある。**取込時にしか得られない情報**は、後から再注釈しても戻らない。棚卸しの実務的な結論は次の 3 行に集約される。

1. **今すぐ決める(不可逆)**: 取込時にしか得られない 10 項目のうち、安価で効くもの(着信経路、終了理由、CRM ケース ID、ターン別 ASR 信頼度、転送後の担当)は v0.3.1 の取込設計に入れる。
2. **v0.3.1 で追加する(可逆だが目的に直接効く)**: 動機、オペレータ行動、提案、混乱の解消、横断フラグの 11 項目。既存表は変えず、列と表を足す。
3. **保留(可逆で、要件が出てから)**: 用件間関係、感情推移、数量などの 14 項目。

初版は層別(ソース / 構造 / 意味 / 横断 / メタ)に並べていたが、判断に必要なのは「回復できるか」と「いつ決めるか」なので、本版はその軸で並べ直した。項目 ID(S/T/C/X/M)は初版のまま残し、新たに見つけた 3 項目(S15, S16, M7)を追加した。初版の集計表は本文と件数が合っていなかった(本文 55 項目、集計 49 件)ため、§7 で数え直している。

凡例: 区分 = ◎ 保持 / ○ 部分保持・導出可 / × 注釈層にない。影響 = 目的 (a) 入電増の真因、(b) わかりづらいパターン、(c) それ以外の一般的な VOC・運用分析、(q) 品質管理。

**不変条件の追加候補**

- `turn_flags.quote` の逐語一致(I4 と同型)
- `confusion_resolved` は `confusion_type <> 'none'` のときのみ非 NULL

## 9. 与えられる保証の正確な言い方

- 「情報が落ちない」保証はできない。
- 言えるのは 4 点。(1) 書き起こしの範囲で原文は無損失に残る。(2) 注釈層の判断列は原文の位置を指す(M7 の例外を除く)。(3) 注釈層にない情報は新しい表と run で後から追加でき、既存の集計は壊れない。(4) 取込時にしか得られない情報は §2 の列を取込設計に含めれば失われない。
- 残る本質的な損失は、閉じた語彙に潰す時点で消えるニュアンス(§4)であり、原文と根拠引用へのドリルダウンで補う。
