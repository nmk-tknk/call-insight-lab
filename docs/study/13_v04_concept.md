# v0.4 コンセプト: 注釈は「構造」と「明言」だけ。判断は集計時の規則で導く

- 作成日: 2026-09-20
- 位置づけ: 依頼者との議論(事実と推論の分離、推論は集計時の工夫で覆う、感情は表出のみを事実とする)の結論。06 の原則 1〜5 を前提に、原則 6 を加える。
- DDL: [`poc/schema/v0_4.sql`](../../poc/schema/v0_4.sql)(`v0_3.sql` → `v0_3_1.sql` の後に適用する追加のみの差分)。検査: [`poc/schema/check_v0_4.py`](../../poc/schema/check_v0_4.py)

## 0. 要点

- **LLM が注釈層に書くのは 2 種類だけ**: 構造(局面、用件の切り出し、ターン帰属)と、発話行為(誰が何を明言したか。必ず引用付き)。
- **混乱の型・動機・結果・受容・横断フラグ・感情は保存しない。** 発話行為と業務知識表(既知の誤解一覧)から SQL のビューで導く。分析用ビューの列名は v0.3.1 と同じなので、既存の集計はそのまま動く。
- **判断の定義を変えても再抽出は要らない。** ビューの SQL を直すだけで、過去分も含めて数字が変わる。差分再実行が要るのは、明言の種類や対象が語彙に足りないときだけになる。
- **失うのは、明言されていない含意だけ。** 「述べていない動機」は不明として数える。どれだけ失うかは第 1 段で「推論あり抽出」と比較して測る。
- **感情は表出のみ。** 「腹が立つ」「助かりました」は事実として記録し、口調からの推定はしない。内面の推定が要る場合は「推定」と名の付く別の run に隔離する。

## 1. 原則 6: 明言だけを注釈し、判断は導出する

06 の原則 2 は「自由記述は集計に使わない」だった。v0.4 はこれに「**推論した値も注釈層に書かない**」を加える。理由は 3 つ。

1. **再現性。** 「なぜこの通話が誤解と数えられたか」が、LLM の判断ではなく「主張 A にオペレータの訂正 B が続いた」という規則で説明できる。誰が集計しても同じ数字になる、という当初の目的に最も直接に効く。
2. **変更の安さ。** 判断の定義は必ず揺れる。ビューに置けば、定義を直すのは SQL の修正で済み、10 万件を LLM に回し直す必要がない。
3. **抽出の易しさ。** 明言の記録は引用の逐語一致で全件を機械検証でき、小型モデルの守備範囲が広がる。2 run 一致が要るのは構造だけになる。

例外は構造(用件の切り出し、帰属、局面の境界)である。これは明言ではなく対話構造の解釈で、集計時には導けない。主観の度合いは低く、参照整合(I1〜I3)と 2 run 一致で機械的に検証できるので、注釈層に残す。

## 2. 発話行為の語彙

「誰が / 何をした / 何について / どの側面 / 値 / 引用」を 1 行とする。値は行為ごとに閉じた語彙を持つ。

| 話者 | 行為 | 値の語彙 | 導く判断列 |
|---|---|---|---|
| 顧客 | 照会する / 変更を依頼する / 申し込む / 解約する / 不具合を報告する / 苦情を言う / 確認する / 提案する | — | 行為 × 対象 × 側面(用件の主たる行為) |
| 顧客 | 経緯を述べる | きっかけ | きっかけ、きっかけの対象 |
| 顧客 | 理由を述べる | 動機 | 動機(述べなければ不明) |
| 顧客 | 主張する(事実についての認識。正誤は問わない) | 主張コード | 間接的な誤解(訂正が続く、または既知の誤解一覧にある) |
| 顧客 | 理解困難を表明する | — | 直接の混乱 |
| 顧客 | 案内済みに言及する | — | 確認のための入電 |
| 顧客 | 了承する / 不服を述べる | — | 受容、混乱の解消、結果 |
| 顧客 | 以前の連絡に言及する | — | 再入電の示唆 |
| 顧客 | 感情を表出する | 怒り / 不満 / 不安 / 困惑 / 感謝 / 安堵 | 通話の開始時・終了時の感情(表出のみから) |
| 顧客 | 意向を表明する | 解約 / 他社乗換え / 継続 | 解約の兆し |
| 顧客 | 上席を求める / 暴言・脅迫 / 制約を述べる / 知らなかったと述べる / 数量を述べる | — | 横断フラグ、数量 |
| オペレータ | 説明した / 訂正した / 再発行した / 変更した / 上席に上げた / 折返しを約束した / 断った / Web を案内した / 引き止めを提案した | — | オペレータ行動、結果、間接的な誤解(訂正) |
| オペレータ | 断定的に保証した / 謝罪した / 保留した / 転送した / 本人確認した | — | コンプライアンス懸念、保留・転送の注釈、局面の補助 |

## 3. 判断列の導出規則(`v_issue_derived` ほか)

| 判断列 | 規則 |
|---|---|
| きっかけ | 顧客の「経緯を述べる」の値。なければ不明 |
| 動機 | 顧客の「理由を述べる」の値。なければ不明。**推し量らない** |
| 混乱の型 | 「理解困難の表明」があれば直接。なければ「主張」に (a) 同一用件で後続するオペレータの「訂正」があるか、(b) 主張コードが既知の誤解一覧にあれば、間接(誤解)。なければ「案内済みへの言及」があれば間接(確認)。それ以外は none |
| 混乱の対象 | 採用した行為の対象 |
| 混乱の解消 | 混乱の行為より後に「了承」があれば解消、「不服」があれば未解消、どちらもなければ不明 |
| 受容 | 顧客の最後の「了承 / 不服」 |
| 結果 | オペレータの「上席に上げた」→ 上席移管。「折返し約束」→ 折返し。「説明・変更・再発行・Web 案内」があり不服がなければ解決。不服がある、または対応行為がなければ未解決。それ以外は不明 |
| 再入電の示唆 | 「以前の連絡に言及」があれば真 |
| 側面 | 用件の主たる依頼行為の側面 |
| 横断フラグ | 意向表明(解約 / 乗換え)→ 解約の兆し。暴言 → ハラスメント。オペレータの断定的保証 → コンプライアンス懸念。上席要求、感謝の表出 → 称賛、制約 → 利用上の制約、知らなかった → Web 手続きの不認知 |
| 感情(通話) | 最初の 25% のターンの表出から開始時、最後の 25% から終了時。否定的な表出があれば negative、なければ肯定的があれば positive、なければ neutral |
| 保留・転送 | オペレータの「保留 / 転送」の発話から。時間はターン時刻で近似 |

規則はこのビューが唯一の定義であり、変更は語彙版と同じく履歴に残す。

## 4. 業務知識表

`known_misconceptions`(既知の誤解一覧)は、業務側が保守する表である。「顧客がこう主張したら、それは誤解である」を主張コードで持ち、正しい事実を添える。オペレータの訂正がなくても、この表に載っていれば誤解と数える。初期値として自動車保険の 8 件(等級が上がれば必ず下がる、無事故なら上がらない、ゴールドは即反映、控除対象、別居の子も家族、証券不着は未契約、二重請求、年齢条件は記名被保険者のみ)を置いた。この表を直すことも、LLM を回さずに数字を変える手段になる。

## 5. v0.3.1 との互換

- `issues` の判断列は表として残る。v0.4 の run では仮値(unknown / none / false / NULL)のまま触らず、I13 でそれを検査する。
- 分析用ビュー `v_issues` / `v_calls` / `v_turn_flags` / `v_call_flags` / `v_agent_actions` は列名・列数を変えずに置き換え、run のスキーマ版が 0.4 以上なら導出値を返す。v0.3.1 の run と v0.4 の run が混在しても同じ SQL で集計できる。
- `turn_flags` / `agent_actions` / `call_annotations.emotion_*` は v0.4 では書かない(導出で返す)。
- 追加: `acts`、`known_misconceptions`、`masked_spans`(取込層のマスキング結果)、`issues.aspect_code`、語彙 act / aspect / claim / emotion_kind / intent、目録で起票した選択肢 6 件。
- 不変条件の追加: I10 発話行為の逐語一致、I11 話者と行為の整合、I12 値の語彙整合、I13 v0.4 run の判断列が仮値であること。

## 6. 目録(12)への影響

- 側面(S8)、保留・転送の注釈(P3)、マスキングのログ(P5)、発話単位の感情(P4)、数量の言及(P2)は、いずれも v0.4 の表・行為で表せる。P2 と P4 は抽出指示に含めるかどうかの運用判断になった。
- 「解釈を含む」とした 16 問は、「導出規則を含む」に変わる。答えには規則の版が添えられ、LLM の判断ではなく規則で説明できる。
- 判定に変更はない(◎ 31 + 側面で 3 → 34、選択肢の追加で 5 → 39。残りは取込データに依存する 5 問)。

## 7. 第 1 段で測ること(v0.4 固有)

| 項目 | 測り方 |
|---|---|
| 明言の再現率・適合率 | 合成の正解(発話行為の一覧)と抽出 run を照合。行為の種類ごと |
| 導出値の一致 | 正解の発話行為から導いた判断列と、抽出 run から導いた判断列の一致率。規則は同じなので、差は明言の抽出誤りだけに起因する |
| 推論との比較 | 同じ 300 件を「推論あり抽出」(v0.3.1 方式)でも処理し、混乱の型・動機・結果の再現率と不明率を比べる。**v0.4 が失う量の実測** |
| 不明率 | 動機・受容・結果の「不明」の割合。実運用で許容できる水準かを依頼者と決める |
| 小型モデルの守備範囲 | 発話行為の抽出を小型モデルで行った κ。構造だけ中位にする構成(11 §A5 案 2)が成立するか |

## 8. 合成コーパスへの影響(10 の改訂)

- 正解は発話行為の一覧として保存する(`annotator = 'synthetic:<gen_id>'` の run の `acts`)。判断列は保存せず、正解からも導出する。
- 生成仕様で「顧客に動機を言わせるか、匂わせるだけか」「オペレータに訂正させるか、既知の誤解一覧に任せるか」を乱択し、明言と含意の比率を制御する。これが §7 の「失う量」の測定条件になる。
- 感情は表出の有無・種類・位置を仕様で決め、口調は生成しない。
- 第 2 段の封印内容は「急増の真因 1 本」に加え、目録の代表的な問い(1, 2, 6, 12, 20, 21, 27, 29, 40)に対応する「埋め込んだ事実の一覧」とする。
