## 0.1 この目録の役割

依頼者の本来の問いは「特定のテーマを拾えるか」である。「用件が解決したか」「未解決の内訳が代理店専用手続きか」もテーマであり、行為 × 対象だけがテーマではない。この曖昧な問いは 3 つに分かれる。

1. **表現できるか**: テーマを構造層の条件式で書けるか
2. **値があるか**: 条件に使う値が語彙にあるか(なければ「その他」に落ち、語彙進化で足す)
3. **信頼できるか**: 抽出が明言を正しく拾うか(κ、逐語一致)

目録が解像度を上げられるのは 1 と 2 である。3 は PoC の実測でしか分からない。したがって目録の使い方は、**45 問を個別に採否することではなく、問いに現れる条件を族に分け、各族に構造層の置き場があるかを確かめること**にある(§2.1)。45 問は 7 族を網羅する試験集として残し、第 2 段の合成コーパスで再現を試す材料にする。

依頼者にお願いすること: (a) 社内で「特定のテーマ」と呼ばれるものの中に §2.1 の 7 族で書けないものがあれば、その例を挙げる。(b) 7 族の中で値の粒度が足りないと感じる族を指摘する。§1 の採否欄は任意(明らかに来ない問いに印を付ける程度でよい)。

## 0.2 判定の読み方

v0.4([02_schema.md](02_schema.md))では、LLM が注釈するのは**構造**(局面、用件の切り出し、ターン帰属)と**明言**(発話行為: 誰が何を言葉にしたか、引用付き)だけで、混乱・動機・結果・受容・横断フラグ・感情は**導出規則**(SQL のビュー)で明言から導く。問いの判定は次の 4 種類。

| 判定 | 意味 | 数字の性質 |
|---|---|---|
| ◎ | 構造と明言だけで答えられる | 事実の集計。引用の逐語一致で全件検証できる |
| ◎規 | 導出規則を含む(混乱の型、動機、結果、受容、横断フラグ、感情のいずれかを使う) | 事実に規則を当てた集計。規則は版管理され、答えに規則の版が付く。明言されていない分は「不明」として数える |
| △ | 近似でしか答えられない | 注記のとおり |
| 取込 | 書き起こし以外のデータ(ターン時刻、オペレータ ID、顧客 ID、CRM)が要る | スキーマでは塞げない。§3 |

各問いは「対象 / 軸 / 指標 / 比較」の 4 要素に分解してある。深掘り(数字から個別通話へ降りる)は全問い共通で「根拠引用 → 原文、一覧には要約」なので列にしない。項目名は平易な呼び方で書く。

## 0.5 用語の定義

| 用語 | 定義 |
|---|---|
| **用件** | 顧客がその通話で達成しようとした目的 1 つ。「行為 × 対象(× 側面)」で表す。分割・統合の規則: (1) 対象が違えば別の用件(保険料の照会と住所変更は 2 件)。(2) 同じ対象に対する行為が自然に進んだもの(照会 → その場で変更依頼)は 1 件とし、主たる行為は最後の依頼行為。(3) 本人確認や保留で中断され、後で同じ対象に戻ったものは同じ用件(非連続)。(4) 粒度は対象マスタの粒度に従う。「運転者限定」が 1 対象で、「別居の子」は側面(適用範囲)。(5) オペレータ起点の提案(特約の勧め)は用件ではなくオペレータ行動。顧客が応じて申し込めば、その時点で用件になる |
| **テーマ** | 分析者が定義する用件の集合。構造層の項目の条件式で表す(例: 行為 = 照会 かつ 対象 ∈ {保険料の増減理由, 等級, 料率改定})。粒度は自由で、対象マスタの親で丸めた粗いテーマから、行為 × 対象 × 側面の細かいテーマまで作れる。定義は版管理して保存し、誰が実行しても同じ集合になる。構造層の項目で書けない条件が要るなら、それは不備(原則 5) |
| **取りこぼした用件**(#28) | 顧客が目的発話で述べたが、議論の局面に一度も現れないまま通話が終わった用件。「保険料の件と、住所変更もお願いしたい」と言ったのに住所変更に触れず終わった場合など。**未解決**(議論したが解決しなかった)とは別で、構造(局面とターン帰属)だけから決まる事実 |
| **受容 / 不服**(#30) | 顧客が説明や対応の後に、受け入れる旨を言葉にしたものが「了承」(「わかりました」「それで結構です」「納得しました」)、受け入れない旨を言葉にしたものが「不服」(「納得できない」「おかしい」「それでは困る」)。相槌だけの「はい」は了承と数えない(語彙の除外基準に書く)。どちらもなければ**不明**として数え、「納得しなかった」には含めない。数字は必ず「不服 N / 了承 M / 不明 K」で出す |
| **経路**(#17) | 顧客が電話に至るまでに何を見て、何を試したか。「経緯を述べる」の明言を 1 用件に複数持てるようにし、順序付きで並べたもの(通知を見た → マイページで試した → 電話)。集計は最初の経緯(きっかけ)と、経路の型(順序の組合せ)の両方で行う |

## 2. 集計

### 2.1 テーマの文法: 条件の 7 族と置き場

テーマ = 7 族から選んだ条件の組合せ(AND / OR)。7 族に置き場がない条件が要るテーマは不備。

| 族 | テーマの条件に使うもの | v0.4 での置き場 | 現れる問い |
|---|---|---|---|
| 何についてか | 行為、対象(親で丸める)、側面 | 用件の主たる行為 + 対象マスタ + 側面 | ほぼ全部 |
| どう至ったか | きっかけ、きっかけの対象、経路(順序) | 「経緯を述べる」(複数、順序。v0.4.1 S15) | 2, 11, 17, 18 |

## 4. 採否の判断で決まること

- **不採用**にした問いは、その問いのための集計・レシピを作らないだけで、**抽出の範囲は変えない**。発話行為の種類は業種によらない役割の一覧であり、問いの有無で増減させると構造化が問いに依存してしまう([01_concept.md](01_concept.md) M10)。検出されたときに数行増えるだけなので、常に全種類を抽出する(案。[open_issues.md](open_issues.md) A7)。「数量を述べる」も同様に常に抽出し、問い 9 の採否は集計を作るかどうかだけを決める。

## 5. 分析手順(レシピ、案)

### 5.1 特定テーマの入電増加の真因(目的 a)

1. テーマを定義する(構造層の項目の条件式。§0.5)。
2. 該当件数の時系列を出し、急増期間と比較用の平常期間を決める。**分母(総入電数)で正規化する。**
3. 急増期間と平常期間で、該当通話のファセット分布を比較する。用件、きっかけ、対象、混乱の対象、結果など。差が大きい順に並べ、効果量と信頼区間を出す。
4. 差が大きい軸について、**両期間から無作為抽出した根拠引用を並べて読む。** ここで仮説が立つ(「9 月の改定通知の文面 X が誤解を生んでいる」等)。
5. 仮説を検証する。仮説を新しいテーマ(条件式)として集計し、時系列が急増と一致するか、急増期間に集中しているかを確認する。
6. 反証を探す。仮説に該当しない急増分がどれだけ残るかを示す。

「誰でもそれっぽい分析」は、この手順の 2(分母)、3(比較対象)、6(反証)を飛ばして 4(引用)だけをやることで生まれる。ツールはこの手順を**飛ばせない形**で提供する。分母・比較期間・両側からの無作為引用・未説明残余を省略できない形にし、結論を書くのは人とする。未決の点は [open_issues.md](open_issues.md) R1〜R5。

### 5.2 「わかりづらい」と訴えるパターン(目的 b)

混乱ありの用件を混乱の対象で集め、件数・推移・下流コスト(再入電、未解決、否定的な表出)で順位付けし、各群の根拠引用を読む。訴え方の 3 区分(直接 / 間接・誤解 / 間接・確認)と導出規則は [02_schema.md](02_schema.md) §4.2。

## 6. 汎用性の見立て(案)

- **汎用にできる部分(厚い)**: 構造化抽出、品質ゲート、期間比較の統計。目的が変わっても再利用される。
- **目的ごとに作る部分(薄い)**: 分析レシピ。「比較軸を選び、順に表示する」程度の薄さで、1 本あたり数日で追加できる。
- **汎用にしてはいけない部分**: 結論を出す工程。ここを LLM に委ねると現状の課題([01_concept.md](01_concept.md) R1)に戻る。

「様々な分析目的に汎用で使えるものを作る」は、「汎用の答えを出す装置」なら筋が悪く、「汎用の証拠と手順を用意し、答えは人が出す装置」なら筋が良い。汎用性の測り方は §0.1(表現できるか / 値があるか / 信頼できるか)。2 つの目的 (a)(b) はどちらも少数の汎用ファセットから組み立てられる。(a) は「テーマ該当通話の時系列」+「急増期間と平常期間のファセット分布の差分」、(b) は横断的なファセット(混乱とその対象)であり、目的固有のものは薄く、共通基盤は厚い。

## 7. できること・できないこと(案)

| できる | できない(別の単位・手段が要る) |
|---|---|
| 用件数ベースの件数・割合・推移・セグメント比較 | 応対品質のコーチング(発話行動の別スキーマ) |
| 急増の真因候補をタグの組み合わせの差として提示 | 語彙にない真因の即時命名(語彙の扱いは [open_issues.md](open_issues.md) S17) |
| 「わかりづらい」対象と訴え方の特定 | 言い方・温度感の解釈(口調からの感情推定) |
| 述べられたが議論されなかった用件の検出 | 顧客ジャーニー(顧客単位テーブルと顧客 ID が要る) |
| 本人確認・保留の所要と位置(ターン時刻がある場合) | 施策効果の因果的検証(実験設計が要る) |
| 解決状況と再入電の自己申告の整合 | 解約予測(目的変数との結合と学習が要る) |

「この基盤で答えられない問い」の一覧をツールの仕様の一部にする。範囲外の問いは人の読解に回すと決めておくことが、範囲を広げることと同じくらい重要。
- **追加**された問いは、同じ 4 要素に分解して判定を付ける。構造と明言で埋まらなければ、それが次の不備の起票になる。
- **修正**は、指標や比較の取り方(分母、期間、セグメント)の指定として受け取り、分析レシピの既定値に反映する。
