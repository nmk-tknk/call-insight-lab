# 0013: 語彙の不足は列挙の失敗として扱い、抽出前に業務側の目録から語彙を完成させる

- 状態: 草案
- 日付: 2026-09-22
- 覆す: なし(0001 の「選択肢は育てる」の運用を、抽出後の育成から抽出前の列挙に改める。0001 の 3 層と項目固定は変えない)
- 覆された: (後から追記のみ)

## 決定

1. 「語彙に該当がない」はスキーマの失敗であり、常態ではない。目標は `other` 率ゼロ。`other` は語彙育成のきっかけではなく失敗の警報とする。
2. 対象マスタは通話から発見するのではなく、業務側の目録(書面とその部位、手続き、補償・特約、用語、画面、窓口・代理店などの相手方)から抽出前に作る。完全性の判定は「合成コーパスに現れる対象語がすべてマスタに当たる」こと。
3. 主張コード(業種固有の誤解の一覧を注釈時に当てる方式)を廃止する。「主張する」も他の行為と同じく 対象 × 側面 + 引用 で持つ。既知の誤解一覧は 対象 × 側面 で引く表に改める。注釈に問題固有のコード表を持ち込まない。
4. 汎用の値(きっかけのライフイベント、側面、理由)は業種によらない閉じた一覧として抽出前に完成させる。側面に「対応・態度」を足す。
5. それでも `other` が出たときの修復は、原文ではなく該当行の引用を再分類して行う(修復手順であり通常経路ではない)。

## 理由

A1 の 14 例で不足した 6 件(同条件更新、証券の割引欄、代理店とその連絡先、不満の理由、ライフイベントの種類)は、いずれも業務側が通話を読まずに列挙できたものである。問いが来てから値を足す運用は、原則 5「覆えない問いはスキーマの不備」を骨抜きにする。v0.4 は注釈を構造と明言に限ったが、主張コードだけは問題固有の判断表を注釈に残しており、そこが不足の主因だった。
