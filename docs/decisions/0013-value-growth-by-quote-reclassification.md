# 0013: 選択肢の追加は引用の再分類で行い、原文への再実行は行為の追加に限る

- 状態: 草案
- 日付: 2026-09-22
- 覆す: なし(0001、0002 の「選択肢は育てる」「差分で埋め直す」を、費用が測れる形に具体化する)
- 覆された: (後から追記のみ)

## 決定

1. 原則 1 が保証するのは「選択肢が足りなくなることが少ない」ことではなく、「選択肢が足りなくても、塞ぐ費用が原文の再実行に比べて無視できる」ことである。選択肢の不足は常態として扱う。
2. 選択肢(値・対象)の追加と細分化は、原文ではなく **発話行為の引用**(`acts.quote`)を再分類して行う。親の値はそのまま、子の値を引用から決める。親の件数は変えない。
3. 原文に LLM を当て直すのは、発話行為の**種類**を足したときに限る。その場合も局面と用件の帰属(第 1 段)は再利用し、発話行為の抽出(第 2 段)だけをやり直す。
4. 引用だけで再分類できるように、`acts` に `value_text`(値を表す短い正規化語句。`other` のときだけでなく常に)を持たせ、「経緯・理由・主張」の引用は接続語ではなく事柄を含む範囲を切り出す規則を抽出指示に置く。
5. 上記が成り立つかを PoC 第 1 段の合否に加える。(a) 引用充足率: 子値の再分類を引用だけで決められた率 ≥ 0.9(残りはターン本文で決める)。(b) 語彙欠落時の取りこぼし率: 対象・値を意図的に語彙から外して抽出し、それでも行為が `other` + 引用として残る率 ≥ 0.9。どちらかを下回れば、原則 1 の保証は成り立たないものとして設計を見直す。

## 理由

A1 の 14 例で 6 例が値・対象の不足だった。今後も不足は続くので、追加のたびに月 1,000 USD 規模の再抽出が要るなら原則 1 は成り立たない。v0.4 では値が引用に対する分類なので、追加は該当する親の引用(数万件、1 件数十トークン)を小型モデルで再分類すれば済み、費用は全件再実行の 1/100 程度になる。ただし「引用に事柄が含まれる」「語彙にない値でも行為が抽出される」は仮説であり、測ってから前提にする。
