# 決定記録

## 結論と履歴

- **結論は [DECISIONS.md](DECISIONS.md) の 1 ファイルだけ。** 現在有効な決定の全文と、各決定の根拠発言(依頼者の言葉と日付)を置く。決定ではない設計(設計者の仮置き)も同じ文書の §5 に列挙し、決定と混同しないようにする。
- **番号付きの記録(`NNNN-<題>.md`)は履歴。** 提案(草案)と、その承認・却下の経緯を残す。結論はここに書かない。承認済みの記録は書き換えない。
- 両者が食い違えば DECISIONS.md が正。

## 規則

1. **提案は番号付きの草案で出す。** `NNNN-<題>.md`。番号は連番で欠番を作らない。状態は `草案`(編集自由)か `承認済み`(以後は不変)。
2. **承認されたら、DECISIONS.md に結論を書き込み、草案の状態を承認済みにする。** DECISIONS.md の各行には根拠発言を付ける。根拠発言で裏付けられないことは書かない。
3. **覆すときも新しい草案を出し、承認後に DECISIONS.md の該当行を書き換える。** 旧記録には `覆された: MMMM` の 1 行だけを追記してよい。
4. **docs 配下の文書と DECISIONS.md の編集は、承認後の適用ターンに限る。** 編集の前に `docs/decisions/APPLY` に記録番号と日付を書き、終わったら削除する(hook が検査する。CLAUDE.md 参照)。docs/01〜06 は DECISIONS.md の決定を説明する文書であり、決定に無いことを決定のように書かない。
5. **記録に書くのは提案と承認の経緯だけ。** 議論の候補案は会話に残す。

## テンプレート

`0000-template.md` を複製する。必須の見出しは 決定 / 覆す / 理由 / 影響を受ける文書 / 承認 の 5 つ。承認欄には依頼者の発言をそのまま(要旨ではなく引用で)書く。
